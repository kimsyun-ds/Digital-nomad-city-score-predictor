## Project Overview

The **Digital Nomad City Score Predictor** is a command-line application built in Python that uses supervised machine learning to estimate a city's suitability score for digital nomads — people who work remotely while traveling the world.

The tool trains three regression models (Linear Regression, Random Forest, and MLP) on a dataset of 730 cities sourced from Nomad List (via Kaggle), comparing their performance and automatically selecting the best model. Users can then interact with the program through a bilingual menu to predict scores for new cities, view ranked recommendations, and export visualization charts.

---

## Why This Project?

Since COVID-19, remote work has expanded dramatically, and the number of digital nomads worldwide has surged. Governments and cities are now actively competing to attract remote workers by improving infrastructure, offering special visas, and reducing living costs.

However, most existing information about "good cities for nomads" comes from:
- Subjective community reviews and blog posts
- General tourism or expat living guides
- Non-data-driven rankings

This project addresses that gap by building a **data-driven, machine learning-based prediction system** that objectively scores cities using quantitative urban features. The result is a reproducible, open source tool that anyone can run, extend, or contribute to.

## Dataset

|----------|--------|
| Source | Kaggle — *World Regions and Nomadscore* (based on Nomads.com / Nomad List) |

## Installation

### Requirements

- Python 3.8 or higher
- pip (Python package manager)

### Step 1 — Clone or download the project

```bash
git clone https://github.com/<your-username>/nomad-predictor.git
cd nomad-predictor
```

Or download and unzip the project folder manually.

### Step 2 — Install dependencies

```bash
pip install -r requirements.txt
```

This installs all required libraries in one command. See [requirements.txt](requirements.txt) for the full list.

### Step 3 — Verify the dataset is present

Make sure `cities_predict.csv` is in the same folder as `predictor.py`. The script will not run without it.

## How to Run

```bash
python predictor.py
```

On first launch, the program will:
1. Ask you to select a language (`en` for English, `ko` for Korean)
2. Load the dataset from `cities_predict.csv`
3. Train all 3 models (takes approximately 10–30 seconds)
4. Display model performance results
5. Show the interactive menu

## Machine Learning Models

### Models Trained

| Model | Description |
|-------|-------------|
| Linear Regression | Baseline model; fits a linear relationship between features and nomad score |
| Random Forest | Ensemble of 200 decision trees; handles non-linear relationships and feature interactions |
| MLP Regressor | Neural network with 1 hidden layer of 100 neurons, ReLU activation, 1000 max iterations |

### Evaluation Metrics

| Metric | Description |
|--------|-------------|
| R² Score | Proportion of variance in nomad_score explained by the model (higher = better, max = 1.0) |
| MSE | Mean Squared Error — average squared difference between predicted and actual scores (lower = better) |

### Results

| Model | R² Score | MSE |
|-------|----------|-----|
| Linear Regression | 0.3853 | 0.1344 |
| **Random Forest** ✔ | **0.4274** | **0.1252** |
| MLP Regressor | 0.2295 | 0.1685 |

**Random Forest was selected as the best model** with the highest R² and lowest MSE.

> **Note on R² = 0.43:** The nomad_score target variable incorporates subjective community ratings, lifestyle preferences, and cultural factors that cannot be fully captured by objective numeric features alone. An R² of 0.43 is considered meaningful for this type of socially-influenced target variable.

---

## Feature Selection

Initially, all 28 numeric features from the dataset were considered. A Random Forest model was first trained on all features, and feature importance scores were extracted. Features with importance below **0.01** were removed, reducing the final feature set to **19 variables**.

This process:
- Reduced model complexity and training time
- Improved R² from 0.4233 (tuned RF, 28 features) to 0.4434 (RF, 19 features)
- Improved interpretability by removing low-signal noise variables

## Why README.md and requirements.txt Matter

### README.md

A README is the **front door of any open source project**. Without it, even an excellent codebase becomes inaccessible to others. A good README:

- Explains what the project does and why it exists
- Provides clear installation and usage instructions so anyone can run it without prior knowledge of the codebase
- Documents the dataset, models, and results so the project is academically and technically credible
- Lowers the barrier to contribution — open source thrives when others can understand and improve a project


### requirements.txt

Open source software must be **reproducible across different machines and environments**. The `requirements.txt` file:

- Pins the exact library names (and minimum versions) needed to run the project
- Allows any user to recreate the exact environment with a single command: `pip install -r requirements.txt`
- Prevents "it works on my machine" problems caused by version mismatches
- Is especially critical in data science and ML projects, where scikit-learn API changes between versions can silently alter model behavior or cause import errors

Without `requirements.txt`, collaborators must guess which libraries are needed and which versions are compatible — a significant barrier to open source adoption.
